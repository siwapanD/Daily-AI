# DAILY AI — Implementation Plan

## Strategy

Deliver the P0 loop end-to-end first: **Fetch → Analyze → Score → Learn → Experiment → Capture Knowledge → Improve Workflow**. Each phase ends with a checkpoint: `npm run lint && npm run typecheck && npm test && npm run build`.

## Phases

| Phase | Scope | Exit criteria |
|---|---|---|
| 0 Repository analysis | Inspect repo/infra | Done — empty repo, Node 22, PG16, Docker (see architecture.md §1) |
| 1 Foundation | Next.js, Tailwind, Drizzle schema + migration, env, logger, Docker, layout/nav | App runs, DB connects, build passes |
| 2 Discovery | Sources CRUD, RSS, GitHub releases/tags, web change, manual URL, normalize, dedupe, fetch logs, SSRF guard | Real data fetched & stored, no duplicate URLs |
| 3 AI analysis | Heuristic classifier/scorer, LLM gateway (OpenAI-compatible, Anthropic, heuristic), budget, cache, run log, prompts | Articles analyzed, cost tracked, errors handled |
| 4 Today dashboard | Today page, Discover with filters, cards + actions | Morning questions answered on one page |
| 5 Knowledge | Learn briefs, knowledge items, areas, statuses, search, markdown render + export, playbook | Learn → save knowledge → export .md |
| 6 Experiments | Experiment CRUD, results per variant (benchmark), decision, playbook update | Create → record results → ADOPT/WATCH/REJECT/RETEST |
| 7 Radar | Radar rings, auto-update from decisions, technology timeline | Radar visible & editable |
| 8 Digest | Daily digest generation (markdown), history, daily job + cron | Digest generated by job and manually |
| 9 Production | Dockerfile (standalone), compose, health check, auto-migrate, backup/restore scripts, docs | `docker compose up` works, health OK |

## Key decisions

| Decision | Choice | Why |
|---|---|---|
| ORM | Drizzle + postgres.js | Light, SQL-transparent, simple migrations |
| UI mutations | Server actions; REST API in parallel | Less client code; API for automation |
| AI without key | Heuristic provider | System usable on day 1, tests deterministic |
| Scheduler | busybox crond container → HTTP | No workflow engine |
| Migrations in prod | `instrumentation.ts` + advisory lock | Works with standalone output, no extra tooling in image |
| Markdown | `react-markdown` + `remark-gfm` | Safe by default (no raw HTML) |
| Auth | Optional Basic Auth (single user) | Spec: single user; RBAC is a non-goal |

## Risks & assumptions

| Risk | Mitigation |
|---|---|
| Feeds change/break | Source isolation, `last_error` visible in Settings, easy to edit |
| LLM cost overrun | Daily token cap, cheap-first cascade, cache, threshold for strong model |
| LLM returns malformed JSON | Tolerant JSON extraction + zod validation + heuristic fallback |
| GitHub rate limit (60/h unauth) | Optional `GITHUB_TOKEN`; only releases/tags in MVP |
| SSRF via manual URL | DNS/IP validation + manual redirect re-validation |
| DNS rebinding (TOCTOU) | Documented known issue; low risk for single-user deployment |
| No auth by default | `APP_PASSWORD` documented as required for internet-facing deployment |

## Value-first ordering

Budget goes to P0 in task-list order. P1 (radar polish, advanced search, prompt UI) only after P0 passes end-to-end. P2 is out of scope.
