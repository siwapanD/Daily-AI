# Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `/api/health` returns 503 | The database is unreachable. Check `DATABASE_URL` and `docker compose ps db`, then the app logs for `startup migration failed` |
| Everything returns 401 | `APP_PASSWORD` is set: log in with any username and that password. Cron requests need `Authorization: Bearer $CRON_SECRET` |
| A source shows `Private or reserved address not allowed` | The URL resolves to a private IP. Use a public URL, or set `ALLOW_PRIVATE_FETCH=true` for trusted local feeds |
| GitHub source shows `HTTP 403 (rate limited?)` | Set `GITHUB_TOKEN` (env or Settings → Secrets). The collector already falls back to `releases.atom` |
| A feed source keeps failing | The feed URL probably changed. Edit or disable it in Settings; the other sources aren't affected |
| Scores look generic / "Generated by the offline heuristic provider" | No LLM is configured, or the daily token limit was reached. See [ai-provider.md](ai-provider.md) and Settings → AI provider |
| `AI fell back to heuristic: …` on an item | The LLM call failed (bad key, model id, network, malformed JSON). The error is in Settings → LLM usage |
| `Job fetch is already running` | Another run started less than 30 minutes ago. Wait, or mark a stuck `job_runs` row as `error` |
| Nothing on Today | Click Fetch Now, then Analyze Now. Today shows the last 48h (falling back to 7 days) |
| `relation ... does not exist` | Migrations haven't run: `npm run db:migrate` (or `AUTO_MIGRATE=true`) |
| `APP_SECRET_KEY must be set` when saving a secret | Set `APP_SECRET_KEY` (≥ 16 chars) and restart |
| Cron container doesn't trigger | `docker compose logs cron`; `DAILY_JOB_CRON` must be quoted in `.env`; run `docker compose exec cron /usr/local/bin/daily-ai-job` to test |
| Changing the schema | Edit `src/lib/db/schema.ts`, run `npm run db:generate`, commit the new `drizzle/*.sql` |

Logs are structured JSON on stdout/stderr (`docker compose logs -f app`). Job, fetch and LLM history are in Settings.
